# c0dev Known Issues

## Purpose

Record finite admitted residuals that affect current product or verification outcomes without turning this register into a specification, plan, or implementation-gap ledger.

## Orientation

Entries remain subordinate to their owning durable specification or contract. This register does not sequence remediation or declare readiness.

## Terminology

| Term                 | Meaning                                                                   |
| -------------------- | ------------------------------------------------------------------------- |
| Deferred surface     | Finite behavior explicitly outside the current supported bar              |
| Verification gap     | Finite missing evidence against an existing durable behavior or contract  |
| Diagnostics deferral | Finite observable already deferred by its owning specification            |
| Seed                 | `unseeded` or one qualified Change address selected outside this register |

## Register

### `C0-KI-001`

- Kind: Deferred surface.
- Restatement: Ad hoc `apt` changes through `c0 root` are not reproduced after destructive guest recreation.
- Owner: [Specification](spec.md).
- Seed: Unseeded.
- Disposition: Diagnose the boundary and require runtime build inputs for persistent OS changes.
- Retirement: A supported declarative persistence surface supersedes the boundary.

### `C0-KI-002`

- Kind: Deferred surface.
- Restatement: OrbStack host bind mounts cannot serve as a writable OverlayFS upper; direct non-XDG `.local` writes persist in a per-instance Docker volume.
- Owner: [Specification](spec.md).
- Seed: Unseeded.
- Disposition: Redirect XDG state to host `.local`, expose the complete upper through `c0 tools`, and make accept/restore explicit.
- Retirement: The host filesystem can satisfy writable OverlayFS upper/work semantics.

### `C0-KI-003`

- Kind: Deferred surface.
- Restatement: Whole-stage acceptance can include logs, credentials, generated bytecode, and configuration beneath an overlaid path.
- Owner: [Tool-store contract](tool-store-contract.md).
- Seed: Unseeded.
- Disposition: Show every path with `c0 tools --detail`, require explicit host acceptance, and mount only the selected snapshot into that runtime.
- Retirement: A generic non-fragile payload/state authority replaces whole-stage semantics.

## Boundaries

Implementation migration tasks, source refactors, temporary test failures, and unqualified review findings do not belong here. They remain temporal until they either disappear or are separately admitted as finite residuals against a durable owner.
